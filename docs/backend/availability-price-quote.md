# Availability + Price Quote API

Endpoint: `POST /api/v1/availability/quote`

## Input
- serviceId
- date
- quantity (1-100)
- optional optionId

## Production invariants
1. Service must be active and bookable.
2. Availability is checked server-side against the selected booking mode.
3. Inventory reads and booking writes must use transactional locking/version checks.
4. Price is calculated server-side from the active pricing rule.
5. Coupon and Coins eligibility are server-side only.
6. Quote returns opaque availabilityToken + priceQuoteId + expiry.
7. Money values use integer minor units serialized as strings.
8. Booking creation revalidates the token, quote, expiry, inventory and price.
9. A quote never guarantees a booking until the booking transaction commits.
10. The current endpoint fails closed until a real database and quote engine are connected.

No fake inventory, price, partner or availability data is generated by this foundation.
